# 脚本整体审查与优化建议

审查日期：2026-09-30。基线：`main`，提交 `5bc4020`，脚本版本 `3.7.4`。

本轮仅审查、复现和记录，没有修改业务脚本，也没有部署到现网。

## 结论

主要风险集中在失败处理、状态一致性和订阅解析，而不是语法错误。现有 Xray/Sing-box 配置事务、核心替换、数据库锁和累计流量 checkpoint 已有有效保护，应保留。

主脚本共有 31,013 行。可以先修复下面的确定问题，再合并重复逻辑；不建议直接拆分工程或大规模重构。

## 已确认的问题

以下位置均对应审查基线。P1 优先修复；P2 随后修复。服务失败和 nftables 失败采用隔离模拟，未操作现网服务或防火墙。

| 优先级 | 问题与位置 | 已观察到的行为 | 最小修复方向 |
| --- | --- | --- | --- |
| P1 | Snell 停用失败被忽略：`vless-server.sh:30581`，`_snell_apply_users` | 停用分支对 `svc stop`、`svc disable` 使用 `|| true`。两者都失败时仍返回成功，运行中的实例可能继续服务，影响超额、到期及人工停用。 | 传播停用失败，检查运行状态，只有确认停用后才报告成功或发送成功通知。 |
| P1 | nftables 重载先删除旧表：`nft.sh:437`，`reload_rules` | 先 flush/delete，再加载新文件。模拟加载失败后，旧运行规则已经消失；之前的文件备份没有自动恢复。 | 校验候选配置，将本工具表的替换放进一次 nft 事务；失败保留运行规则并恢复持久化文件。 |
| P2 | Snell 用户修改缺少回滚：`vless-server.sh:1507`，`db_set_user_enabled` | 数据库先写入 `enabled=false`，随后 `_snell_apply_users` 失败，函数返回失败，但数据库仍是修改后的状态。 | 将 Snell 状态修改也纳入完整事务，记录配置和原运行状态，失败恢复。 |
| P2 | 全局分流的数据库与配置不一致：`vless-server.sh:16938`、`:17032` | 先保存/删除数据库规则，再重建配置。重建函数备份的是修改后的数据库；失败后运行配置回到旧版，数据库仍保留新状态。删除菜单还会显示成功。 | 在规则修改前开始事务；覆盖受影响的两个核心，统一处理失败与菜单反馈。 |
| P2 | 手动清零流量没有推进 checkpoint：`vless-server.sh:1480`，`db_reset_user_traffic` | 只把 `.used` 设为 0。隔离示例中，旧 checkpoint 为 100，清零时核心累计计数为 150，之后到 160，下次同步记入 60，包含清零前的 50。 | 持锁同步累计计数后再清零，保持 checkpoint 与计量边界一致；Snell 同样处理其计数基线。 |
| P2 | 订阅生成失败覆盖旧文件并返回成功：`vless-server.sh:25427`，`generate_sub_files` | 生成器写出部分内容后返回非零，旧文件已被重定向覆盖，后续 chmod 和成功提示让函数返回 0。菜单也无条件显示“已更新”。 | 先生成全部候选文件，检查每个生成器状态，再发布；失败保留旧内容，调用者检查返回值。 |
| P2 | 明文订阅被部分 Base64 解码破坏：`vless-server.sh:18302`，`parse_subscription` | 对合法 `vless://...` 明文，`base64 -d` 输出部分字节后失败。函数只判断输出非空，仍用这些字节替换原文，最终无法导入。 | 同时检查解码退出码与内容格式；失败使用原文。和 `fetch_subscription` 共用解码入口。 |
| P2 | Clash 导入改变协议语义、丢失末尾节点参数：`vless-server.sh:24053`，`fetch_subscription` | 普通 VLESS TLS+WS 节点被转换为 `security=reality`；处理最后一个节点的重复分支没有保留 WS path/host。已用合成 YAML 复现。 | 正确区分普通 TLS 与 Reality；所有节点调用同一转换函数，统一保留网络与 TLS 参数。 |
| P2 | 订阅元数据读取/写入不完整：`vless-server.sh:24880`、`:24896` | 缺字段时可沿用调用者旧端口/域名；遇到后续非法字段时，前面的变量已经被修改。写入失败又可能被成功的 chmod 掩盖。 | 完整解析到局部候选值，验证字段集合后一次赋值；文件用同目录临时文件写入，逐步检查返回码。 |
| P2 | 数字溢出及 IPv6 校验过宽：`vless-server.sh:24798`、`:24803`、`:24814`、`:24855`；`nft.sh:77` | 两个脚本都接受超长端口 `18446744073709552059`；主脚本接受 IPv4 的超长段、`1:2:3` 和 `2001::1:` 等非法地址。 | 在算术前限制有效数字长度和范围；统一复用严格的 IPv4/IPv6 校验，明确前导零策略。 |
| P2 | 到期 cron 安装失败返回成功：`vless-server.sh:1948` 和 `--setup-expire-cron` 入口 | 安装函数失败后最后调用 `_err`，其返回码为 0；CLI 还直接 `exit 0`。隔离模拟安装失败仍得到成功状态。 | 错误分支显式 `return 1`，CLI 使用实际结果作为退出码。 |

附带确认：`db_get_user_field` 在 `vless-server.sh:1231` 使用 jq 的 `// empty`，会把合法布尔值 `false` 变成空输出。现有主要调用者通常用 `!= true` 判断，未据此认定账号重新启用；建议修复通用字段读取的类型语义，并补充真假值测试。

## 测试本身存在的漏检

`tests/port-users-monthly.sh` 的函数装载列表缺少 `db_get_user_alert_state` 等告警函数。运行相关分支时输出 `command not found`，测试仍显示 PASS。`set -e` 无法保证捕获 `local value=$(...)` 等写法里的失败。

应补齐函数装载与告警断言，并把本轮失败路径变成回归用例。单纯扩大 ShellCheck 禁用列表或统一机械改写 1,131 处 SC2155 提示，不能替代修复实际错误路径。

## 风险与未验证范围

- `nft.sh` 的安装接管流程明确提示并要求确认全量清空规则，因此没有把它归为“未经确认删除”的缺陷。不过它只备份配置文件，未完整保存其他程序在运行时创建的规则；部署时仍需评估与 Docker、UFW 等规则的共存。
- Alpine/OpenRC、真实 Snell 服务故障、真实 nftables 更新均未在对应环境执行；这部分结论来自源码与隔离模拟。
- HY2/TUIC 完成原生配置检查，没有进行 QUIC 客户端端到端测试。
- ACME、Cloudflare 登录/隧道、WARP 注册、第三方出口、外部真实订阅和系统级 BBR 调整未实操；没有为覆盖菜单而修改现网。
- 本地 Windows Git 配置 `core.autocrlf=true`，当前 checkout 的 Shell 文件含 CRLF。直接在 Linux 执行会报语法错误；验证使用 LF 导出副本。后续建议用 `.gitattributes` 明确 Shell 文件为 LF，不把换行转换混入业务修复。

## 建议修复顺序

1. Snell 停用与状态回滚、全局分流事务、nftables 失败保留旧规则。
2. 手动流量清零的计量边界、订阅候选文件发布、cron 的失败退出码。
3. 合并订阅解析并修复 TLS/Reality、末尾节点、元数据与输入校验。
4. 测试漏检、重复刷新、无调用函数及明显无用变量。

每轮只处理一个可验证主题，保留目录结构与接口，完成回归后建立独立 commit。需要触及服务器服务或防火墙的实装，另行给出备份、回滚和执行步骤。
