## 兼容与恢复

- 直接更新脚本即可，不需要重装节点。更新动作不主动修改既有账号、用量、到期日期、路由、TG 绑定或 `traffic_reset` 配置。
- 历史版本已经存成错误数值的配额、非法日期，无法准确推断原始输入意图；请在用户管理中重新设置受影响账号。本次不批量改写旧数据。
- 手动清零不自动启用账号。超额停用账号需要在清零后单独启用；人工停用或已到期账号仍保留原状态。
- v3.7.18 之前生成过错误 Xray 用户路由的安装，升级后仍需重新保存受影响用户的路由，重建配置；不必删除用户或清空用量。
- 到期任务预检查可能安装本来就需要的定时任务；若后续核心配置校验失败，账号按原事务回滚，任务保留用于检查其他已有账号。
- 卸载途中 Nginx 清理失败会保留配置备份并退出；此前已经执行的节点停止步骤不声称整体回滚。脚本更新若恢复本身也被系统拒绝，会报告具体目标及保留的备份位置，不会提示更新成功。

## 验证范围

在 WSL Ubuntu 24.04 私有测试目录中运行 Bash 语法、Python AST、完整 `tests/run.sh` 和新增隔离回归。测试用私有数据库、配置及服务/cron 模型，不登录生产服务器，不改线上配置或真实防火墙，不发送 Telegram 消息。

最终完整套件退出 0，输出 49 个 Shell 入口 `OK`（包含 5 个主动跳过原生检查的包装入口），Po0 JavaScript 回归通过，共 7 项可选原生检查明确跳过。所有工程与测试 Shell 文件语法、所有测试 Python 文件 AST 检查通过。五个修复相关回归文件在未修复基线 `631b36d` 上均能失败检出，在修复版本上均通过。

Windows 挂载目录中的一次完整运行曾在未改动的 Reality 本地 TLS 用例失败；随后该用例单独运行通过，改在 Linux 原生临时目录执行的完整套件也通过。未因此修改 Reality 实现；该次失败原因未确认为产品缺陷或某个特定环境因素，保留为验证过程中的间歇性现象。

另启用 `TG_BOT_NATIVE_TEST=1`：使用真实 Bash/curl 连接本地 HTTP 测试端点，验证长轮询、账号隔离、同批统计合并、回复失败重试及进程组停止清理；原生 systemd 服务生命周期未启用。机器人锁测试另外验证活锁争用、旧目录初始化宽限、孤儿目录恢复、陈旧 PID 记录和 SIGKILL 后内核锁释放。

未提供真实 Xray/Sing-box/Snell/Realm/Nginx 二进制，因此对应的完整核心、客户端与原生服务联调不属于本轮通过范围。内核 nftables、原生 IPv6 接口、真实 Telegram、完整 Alpine/OpenRC 环境也未执行；已有相应测试继续明确标记跳过。GNU/BusyBox flock 兼容模型回归保留。

本次不实现审计报告中的全局 nft 接管设计调整、内部数据结构迁移、批量重启合并或备份自动清理；这些需要另行设计及验证。也不将最后一次采样到核心停止间的计量窗口描述为零漏计。
