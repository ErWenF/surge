# v3.7.5 后续审计：缺陷、功能体验与冗余

审计基线：`09f05add2f260a50fc5db0bd25cb2fd921582b04`，脚本版本 v3.7.5。
审计日期：2026-09-30。

后续处理见 [v3.7.6 修复与验证](followup-fixes-2026-09-30.md)。下文保留原审计基线和复现证据；第 8 项仍有严格零漏计的实现边界，不能据新增收尾采集宣称完全消除。

本轮检查主脚本、nft 管理脚本、辅助脚本、Surge 模块及现有测试。重点沿配置生成、服务控制、订阅管理、流量统计、定时任务、Snell 用户和 Realm 转发的实际调用路径排查。以下问题是这轮继续发现的缺陷，不能用上一轮回归通过来排除。

本轮仅新增本报告及两个隔离复现文件，未修改业务脚本。优先级 P1 表示应优先处理的凭据、服务或配置风险；P2 表示功能正确性、并发或运行状态问题；优化建议不等同于漏洞。

## 一、优先修复的问题

### 1. P1：Sing-box 核心配置可能泄露本机凭据

- **位置**：`vless-server.sh:12243`、`:1002`、`:204`。
- **原因**：渲染器直接重定向生成文件，没有设为 `600`；发布时 `cp -p` 保留候选权限。默认 `umask 022` 下生成并发布的 `singbox.json` 为 `644`，而配置目录为 `711`，允许按已知路径穿越。
- **影响**：本机普通账号或低权限进程可读取用户密码、UUID 等配置凭据。这不是已验证的公网直接下载问题。
- **验证**：调用实际生成和发布路径得到 `644`；在服务器的 `/tmp` 模拟目录中，UID `65534` 成功读取模拟凭据，私有数据库仍不可读。没有读取或展示线上凭据。
- **最小修复**：候选和最终核心配置显式设置 `600`，校验权限失败应中止发布；保留订阅目录所需的穿越权限，避免直接改整个目录权限导致 Nginx 订阅不可用。

### 2. P1：“停止全部服务”遗漏 Snell 多用户实例

- **位置**：`vless-server.sh:14198`，对照多用户分组实现 `:30773`。
- **原因**：直接向 systemd/OpenRC 检查旧的 `vless-snell*` 服务，而实际多用户实例名是 `vless-snellu-<id>`。旧服务不活动时，分组停止操作也不会被调用。
- **影响**：界面提示没有服务需要停止，但多用户实例可以继续运行。
- **验证**：模拟旧服务不活动、用户实例活动，实际 `stop_services` 未执行任何实例停止操作。
- **最小修复**：用已有的 `svc status/stop` 分组分派检查、停止实例，并核对最终状态。不能只修提示文字。

### 3. P1：停用订阅可能误停其他网站的 Nginx

- **位置**：`vless-server.sh:25794`。
- **原因**：仅统计 `conf.d/*.conf` 和 `http.d/*.conf`，没有检查 Debian 常见的 `sites-enabled` 或实际生效的 include 配置。
- **影响**：其他网站仍有启用配置时，也可能执行 `systemctl stop nginx`。
- **验证**：隔离目录存在 `sites-enabled/customer-site`，停用订阅路径仍调用了停止 Nginx。服务命令全部模拟。
- **最小修复**：优先仅移除本脚本的订阅配置，检查有效配置并重载。只有确认 Nginx 为本脚本独占且没有其他站点，才考虑停止。

### 4. P1：重新配置订阅没有完整回滚

- **位置**：`vless-server.sh:25835`、`:25914`、`:26035`、`:26043`、`:26050`。
- **原因**：新配置通过检查前，已经删除旧伪装配置、覆盖订阅 Nginx 配置、保存新元数据并修改 hosts；若重置 UUID，还会提前删除旧订阅目录。检查失败只删除新 Nginx 文件。
- **影响**：失败后旧站点配置丢失，订阅信息和 hosts 却停留在新状态；提前重置 UUID 的分支还可能失去可用的旧订阅入口。
- **验证**：注入 `nginx -t` 失败，旧订阅配置、旧伪装配置均不存在，新元数据和新 hosts 记录仍保留。UUID 提前删除分支由源码确认，未另做故障注入。
- **最小修复**：暂存新配置和元数据，备份本脚本管理的旧文件、hosts 对应记录及旧订阅入口；验证和服务加载成功后再提交、清理旧入口。失败恢复完整状态。

### 5. P2：Nginx 启动失败仍提示订阅配置成功

- **位置**：`vless-server.sh:26055`。
- **原因**：`enable/restart` 返回值没有处理，也没有检查实际运行状态。
- **验证**：配置检查成功、模拟 `systemctl restart` 返回失败，函数仍输出“订阅服务已配置”。
- **最小修复**：检查加载结果和活动状态；失败走第 4 项的回滚，不应显示可用链接或成功提示。

### 6. P2：编辑 Snell 用户会启动原本手动停止的实例

- **位置**：`vless-server.sh:31113`、`:31122`、`:30757`。
- **原因**：编辑路径没有保存、恢复原运行状态；应用配置时，数据库中启用但实际停止的用户会被启动。
- **验证**：用户 `enabled=true`、实例停止，保存编辑后实际应用函数调用 `start`。
- **最小修复**：复用用户变更快照，明确保留编辑前的运行、自启和用户启用状态；只有原本运行的实例才重启。菜单“保存并重启”的文字也应说明实际影响，避免暗中改变停止状态。

### 7. P2：Snell 添加用户在交互输入期间持有数据库锁

- **位置**：`vless-server.sh:30953`、`:30965`、`:30980`。
- **原因**：整个交互函数都放在 `_with_db_lock` 内，安装依赖、网络操作和等待输入也在锁内。
- **影响**：停留在输入界面时，其他数据库写入、流量同步和配额检查会等待；`flock` 路径没有等待时限。
- **验证**：让函数停在读取用户名处，另一独立文件描述符无法获得数据库锁；结束提示后立即可获得。
- **最小修复**：在锁外收集输入和准备依赖；提交时获取锁，重新检查用户名、端口及当前数据库，再执行短事务。

### 8. P2：核心重启仍有统计漏计窗口

- **位置**：`vless-server.sh:940`、`:973`、`:1013`、`:17064`、`:17095`。
- **原因**：只在生成和校验配置前同步累计流量，旧核心在此期间仍能产生新流量；重启后旧计数消失，新进程代次的计数无法补回这一段。
- **验证**：使用实际快照和数据库记账函数，首次累计值为 `100`，校验期间增加到 `150`，重启后又产生 `10`，最终记账为 `110`，实际应为 `160`。
- **最小修复**：定义停止/切换前的统计收尾流程，并让回滚保留收尾后的统计。简单再读一次只能缩短窗口，不能宣称严格零丢失，需要设计可靠的流量停止边界。

### 9. P2：crontab 读取失败或并发修改会丢任务

- **位置**：`vless-server.sh:3559`、`:3572`。
- **原因**：读取失败被当作空表；读、过滤、整体覆盖之间没有锁。标签匹配也按整行子串过滤，可能匹配非本脚本条目。
- **验证**：模拟读取失败后，已有备份任务被覆盖；两个调用读到相同旧表并交错提交，最后只保留一个新增任务。并发用例保留了原有备份任务，证明丢失的是竞争提交的新任务。
- **最小修复**：为本脚本所有 crontab 增删共用一把锁；区分没有任务与读取异常；按明确的行尾标记匹配。外部工具不会遵守这把锁，仍需说明共用 crontab 的维护边界。

## 二、功能正确性和使用体验

### 10. P2：自定义流量告警阈值不按设置执行

- **位置**：`vless-server.sh:29446`、`:3231`、`:3263`、`:30895`。
- **验证**：设置阈值 `70%` 时，Xray 用户达到 `75%` 不告警，因为档位仍固定为 `80/90/95`；设置 `90%` 时，Snell 用户达到 `85%` 已告警，因为 Snell 硬编码为 `80%`。
- **建议**：自定义首个阈值应真正生效，后续档位和 Snell 规则统一；避免菜单显示保存成功但后台忽略设置。

### 11. P2：Realm TCP/UDP 选择写入了错误配置层级

- **位置**：`vless-server.sh:29713`、`:29721`。
- **原因**：`no_tcp/use_udp` 写在 endpoint 顶层，而 Realm 读取的是 endpoint 内的 `network`。全局配置又设置了 TCP 和 UDP 都启用。
- **验证**：实际生成 TOML，确认 UDP/TCP endpoint 都没有 `network` 子表；对照[官方 endpoint 配置结构](https://raw.githubusercontent.com/zhboner/realm/master/src/conf/endpoint.rs)和[全局配置继承逻辑](https://raw.githubusercontent.com/zhboner/realm/master/src/conf/mod.rs)，这些顶层标志不控制 endpoint 的网络选项。因此按官方源码推导，IPv4 规则即使选择单协议，也会继承双协议配置。
- **建议**：使用 `[endpoints.network]` 或对应内联表，TCP 显式 `use_udp=false`，UDP 显式 `no_tcp=true`。
- **边界**：本轮验证了生成结构和官方源码，没有启动真实 Realm 检查监听端口；正式修复时应做真实 TCP/UDP 隔离测试。

### 12. P2：Realm IPv6 监听地址缺少方括号

- **位置**：`vless-server.sh:29719`、`:29720`，输入验证允许 IPv6 的位置 `:29878`。
- **验证**：合法输入 `::1` 生成 `listen="::1:32104"`，未使用 `[::1]:32104`。官方 `build_local` 使用 `ToSocketAddrs` 解析监听地址，见[官方实现](https://raw.githubusercontent.com/zhboner/realm/master/src/conf/endpoint.rs)。
- **建议**：复用主脚本已有的主机端口格式化逻辑，或在 Python 中明确区分 IPv6 并加方括号。真实 Realm 启动验证仍待修复时完成。

### 13. P2：Realm 流量显示混入相同前缀端口

- **位置**：`vless-server.sh:29773`。
- **原因**：按正则子串 `dpt:<port>` 查找，`dpt:443` 也匹配 `dpt:4430`。
- **验证**：两个端口分别为 `100`、`200` 字节，查询 `443` 返回 `300`。
- **建议**：对完整目的端口字段做精确匹配。另外，每次重建转发计数链都会清空计数，菜单应说明统计起点，或在重建前保存累计量。

### 14. P2：Surge 模块仍加载其他仓库的脚本

- **位置**：`scripts/po0fw.sgmodule`、`scripts/Wifi-po0fw.sgmodule`。
- **原因**：模块的脚本地址仍为 `mozisen/surge`，而当前维护仓库为 `ErWenF/surge`。
- **影响**：使用本仓库模块也不会自动加载本仓库 JS 中的修复。这不是判定原作者代码不可信，而是维护和交付路径不一致。
- **建议**：明确模块维护源并统一地址；统计核心预编译包也仍从原仓库下载，应明确这是依赖源还是待迁移的发布源，不能直接盲改二进制下载地址。

### 15. P2：白名单面板误判 IPv4 `/24` 命中

- **位置**：`scripts/po0fw-panel.js:28`，对照 `scripts/Po0fw.js:818`。
- **验证**：返回白名单 `192.0.2.0/24`、当前出口 `192.0.2.5` 时，主脚本匹配函数认可命中，面板却提示未在白名单。
- **建议**：共享或保持一致的严格 IP/CIDR 匹配逻辑，并覆盖精确地址、网段和无效数据。

### 16. P2：WiFi 切换没有确认 API 操作结果

- **位置**：`scripts/wifi-module-switch.js` 的 `$httpAPI` 回调。
- **验证**：模拟错误返回，脚本仍打印“已连接……关闭模块”。这是 Node VM 中的回调逻辑验证，未运行真实 Surge。
- **建议**：识别失败、记录正确结果，并在必要时读取实际模块状态；模块名可配置，避免用户改名后失配。正式修复需对照真实 Surge API 返回格式。

其他体验建议：

- 单用户修改或分流调整会重启整个共享核心，可能中断同核心其他用户的连接。菜单应明确影响范围；热更新仅在核心支持、能验证和回滚时采用。
- 外部订阅有两套解析入口，支持的协议和字段不同；逐行正则解析 Clash YAML 对行内对象、复杂嵌套等格式覆盖不足。导入结果应报告导入数、跳过数和原因，不能只给一个笼统成功提示。
- 订阅重配置自动删除旧伪装站点、写 hosts、重启整个 Nginx，动作范围超过单纯生成订阅。建议把这些动作明确展示，并尽量复用现有站点配置。

## 三、可减少的冗余

以下属于维护建议，当前不应为了清理而直接删除兼容路径或大面积拆文件。

1. **未找到主脚本内调用的旧辅助函数**：`get_user_traffic`、`_backup_core_binary`、`_rollback_core_binary`、`_has_version_updates`、`_get_version_update_info`、`setup_nginx_sub`。删除前仍需检查测试、外部 source 使用和动态分派。
2. **两套订阅/节点解析模型**：`parse_proxy_link` 与 `parse_share_link` 输出字段不同；Clash 中间节点和最后节点还有重复转换分支。上一轮共享 VLESS 转换修复了部分问题，剩余转换仍应逐协议收敛并保留兼容适配。
3. **版本缓存更新入口重复**：`_update_all_versions_async` 与其他后台更新路径写同一稳定版缓存，缺少共同的请求去重和原子写入。宜保留一个缓存写入入口，减少重复请求和临时空缓存。
4. **旧订阅配置函数与现用交互配置函数重复**：先确认 `setup_nginx_sub` 的外部使用情况，再收敛为一个受测试的配置发布流程。
5. **展示和排版重复**：`show_status` 有可合并的相同输出分支；`Po0fw.js` 大量空行和逐参数换行增加审阅成本。这些是可读性问题，不应宣称为明显运行性能问题。

## 四、验证记录和边界

- 本地 WSL 隔离复现：14 个 shell 场景。
- 服务器 `wawo-hk-pis` 隔离复核：相同 14 个 shell 场景；所有服务管理、Nginx、iptables/nft 和网络请求均模拟。只有配置权限读取使用真实 Linux UID 降权子进程，内容全为模拟凭据。
- Node VM：2 个 JS 场景，未向 Surge 或防火墙 API 发请求。
- 新复现文件通过 shell/JS 语法检查；ShellCheck 的 error 级别检查通过。
- 服务器记录：`/root/surge-audit.hsvH3p/deep-audit.log`；相关线上文件哈希及服务活动状态、PID、重启次数前后相同。哈希覆盖本次列举的配置和脚本，以及 root crontab，不代表扫描了整台服务器所有文件。
- 真实 Snell/OpenRC/Surge/Realm 运行环境没有在本轮启动测试。上述服务故障、交互和并发结果是实际脚本函数配合隔离模拟的证据，不能当作所有平台端到端验证。
- 此处“复现通过”表示问题断言成立，**不表示这些问题已修复**。之前回归覆盖的数据库原子性、失败回滚、重复统计等仍有价值，但没有覆盖本报告中的全部路径。
- 已排除两项初步疑点：订阅 UUID 重置会清理旧目录；`--snell-prepare` 启动入口没有调用数据库初始化，不能据此认定为父子数据库锁死锁。

复现文件：`docs/audit-repro-2026-09-30.sh`、`docs/audit-repro-2026-09-30.js`。Shell 场景名称见脚本 `case`；在 Linux 的 LF 检出目录中设置 `AUDIT_REPO` 为仓库绝对路径，再执行指定场景；JS 文件用 Node 直接执行。复现工具创建 `/tmp/surge-followup.*` 模拟目录，不自动清理，便于查看证据。

建议修复顺序：凭据权限 → 全部停止/订阅误停 → 订阅完整事务 → Snell 状态和锁范围 → 统计与 cron → Realm/告警/模块体验 → 冗余收敛。每组先补能在修复前失败的回归用例，再做最小修复和隔离真实环境验证。

这个问题以后可能还会遇到，建议加入 lessons.md：新增运行模式必须逐一核对停止、暂停、卸载、备份、状态显示和订阅入口；涉及失败回滚、并发及权限的检查不能只靠语法或成功路径测试。本轮没有自动修改协作规则。
