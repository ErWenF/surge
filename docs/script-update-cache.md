# 手动更新缓存修复（v3.7.8）

旧版 `perform_script_update` 调用 `_get_latest_script_version true false`，即使用户主动选择“检查并更新脚本”，仍可能读取缓存中的旧版本号，从而提前返回“已是最新版本”。Git 已推送成功也可能出现这个提示。

v3.7.8 的手动更新直接下载当前分支脚本，保留 GitHub blob 和 Bash 语法校验，从该文件提取版本并刷新版本缓存。确认更新后安装同一个已校验文件，不再二次下载可能变化的分支内容。主菜单后台检查仍保留缓存，避免额外网络开销。

下载、完整性校验或版本标识检查失败时，明确报错并保留当前脚本；取消更新和已经最新时清理临时下载文件。旧脚本备份和节点数据库行为保持不变。本次未修改流量周期、核心配置、cron 或服务管理逻辑。

旧版第一次更新可重新下载新版并运行，绕过旧菜单缓存，无需卸载重装。默认 main 分支可能短暂受到 GitHub CDN 缓存影响，急需更新时可使用目标提交 SHA 的 raw 地址；不要凭截图中的当前版本判断远程版本。
