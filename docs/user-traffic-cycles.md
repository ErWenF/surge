# 用户独立 30 天流量周期（v3.7.7）

## 设置方法

- 已有用户：运行 `vless` → `4 用户管理` → `c 设置用户流量周期` → 选择用户 → `1`，确认开通日期后开启。
- 新增用户：在添加用户时，对“按开通日起每 30 天重置流量？”输入 `y`。留空保留原来的全局行为。
- 用户列表显示“30天 / 下次 YYYY-MM-DD”；未开启的用户显示“沿用全局设置”。

## 周期规则

按服务器当地的日历日期计算，重置日期为开通日期加上 30、60、90……天。例如 2026-01-01 开通，依次在 2026-01-31、2026-03-02、2026-04-01 重置，不受每月长短影响。它按日历日计算，不保证恰好在开通时刻后的第 720 小时执行。

重置由现有流量同步任务执行，在边界当天首次成功同步时清零。若该任务已经正常运行，保留原检测间隔；没有有效任务时，开启独立周期会建立/修复流量同步任务。无需额外的每日重置 cron，也不会按每月 30 日处理。

服务器停机或统计读取失败时，不推进周期标记。恢复后补做一次重置，标记推进到当前周期；下次日期仍按原开通日期计算，不改为“恢复后的第 30 天”。

## 兼容旧配置

- 升级脚本不自动给已有用户开启周期，不批量补写开通日期，不清零已有流量。
- 开启时优先使用用户现有 `created` 日期；缺失时要求明确输入真实开通日期，不将升级日期当作开通日期。新增 Snell 用户开始记录开通日期，旧 Snell 用户保持原数据。
- 给已有用户启用周期时，保留当前已用流量，登记当前所在周期，在下一个边界重置。例如 1 月 1 日开通、2 月 10 日才开启，当前用量保留到 3 月 2 日。
- 仅增加所选用户的 `traffic_reset` 元数据；凭证、端口、路由、流量配额、到期日期、TG 绑定和其他自定义字段保持不变。
- 独立周期用户不参加全局每月重置；其他用户继续使用原来的月重置开关和日期。取消独立周期后，该用户重新受全局设置控制，下一次全局检查可能执行月重置。
- 人工清零不会改变开通日期或延后下次周期；重复开启同一开通日期也不会延后已到期的周期。
- 日期缺失、无效、未来日期或错误周期标记不会被用于自动清零。配置中已有同名用户对应多个入站时，拒绝修改周期，避免误改。

周期数据示例（仅用户记录增加字段）：

```json
"traffic_reset": {
  "days": 30,
  "anchor": "2026-01-01",
  "last_period": 0
}
```

## 配额恢复和失败处理

仅因流量超额而停用、且尚未到期的用户会在重置后恢复；人工停用或已到期用户保持停用。运行中的 Xray/Sing-box 在需要恢复认证用户时重建配置、校验并重启所属核心，同核心连接可能短暂中断；原本停止的核心保持停止。Snell 只恢复对应的超额用户实例。

清零前结算累计统计并保存私有数据库备份；恢复认证失败时回滚流量、周期标记和配置。跨核心回滚保留候选配置校验期间结算的其他用户流量。Snell 恢复失败时同时恢复原配置、进程状态和自启状态。API 最后读取与停止核心之间仍有很短的统计窗口，沿用已有统计方案的边界，不能承诺流量误差严格为零。

## 验证

专项测试：`bash tests/user-traffic-cycles.sh`。覆盖旧配置无操作升级、启用保留流量、已有 cron 间隔、闰年、跨年、30 天边界、漏执行补偿、重复执行、月重置互斥、人工/到期停用、停止核心、统计/校验/重启失败，以及第二核心失败时保留其他用户的晚到流量。

真实核心测试：`tests/core-native.py` 验证 Xray SS2022、Sing-box Trojan 的超额停用和周期恢复后的 TCP/UDP 连接、重新计量及其他端口隔离；`tests/snell-edit-native.sh` 在独立网络命名空间验证真实 Snell/nft 周期恢复和启动失败回滚。

全部回归入口：`bash tests/run.sh`。原有每月重置、订阅、核心切换、分流、cron 和 Po0 测试继续运行。
